title: Quickstart
description: Quote and register an AgentDomain identity with the TypeScript SDK and a connected wallet.
---

This example uses the published `@agentdomain/sdk` 0.11.1 on Base mainnet. Supply a wallet account from your
application's secure wallet integration; never commit wallet material to source control.

## Install

```bash
npm install @agentdomain/sdk@0.11.1 viem@2.56.3
```

For workspace development, build the shared and SDK packages from the reviewed
repository root instead:

```bash
pnpm --filter @agentdomain/shared build
pnpm --filter @agentdomain/sdk build
```

## Quote and register

```ts
import {
  AgentDomain,
  RegistrationPaymentRejectedError,
  RegistrationPendingError,
} from '@agentdomain/sdk';
import { createWalletClient, http } from 'viem';
import { base } from 'viem/chains';
import type { PrivateKeyAccount } from 'viem/accounts';

export async function registerAgent(account: PrivateKeyAccount) {
  const walletClient = createWalletClient({
    account,
    chain: base,
    transport: http(),
  });
  const agentDomain = new AgentDomain({ walletClient });

  const quote = await agentDomain.quote({
    preferredName: 'helpful-bot',
    tld: 'com',
    registerBasename: true,
    basenameLabel: 'helpful-bot-ai',
    registerEns: false,
    emailUsername: 'agent',
    years: 1,
  });

  console.log(`Registration total: ${quote.totalUsdc} USDC`);

  try {
    const identity = await agentDomain.register({
      wallet: account.address,
      ownerAddress: account.address,
      preferredName: 'helpful-bot',
      tld: 'com',
      registerBasename: true,
      basenameLabel: 'helpful-bot-ai',
      registerEns: false,
      emailUsername: 'agent',
      years: 1,
    });

    if (identity.provisioningStatus && identity.provisioningStatus !== 'completed') {
      console.log(identity.registrationId, identity.provisioningStatus);
    }

    return identity;
  } catch (error) {
    if (error instanceof RegistrationPaymentRejectedError) {
      // This submission was rejected before settlement. Do not automatically resend.
      console.log(error.code, error.serverCode, error.message, error.handle);
    } else if (error instanceof RegistrationPendingError) {
      // Retain this non-secret handle for payer-authenticated recovery, not another payment.
      console.log(error.reason, error.handle);
    }
    throw error;
  }
}
```

SDK 0.11.1 creates one request-bound EIP-3009 payment signature and submits the exact challenged
request once. It preserves the complete accepted requirement, including the opaque
`extra.registrationQuote` and ISO `extra.quoteExpiresAt` from the initial `402`. It validates the
bound Base USDC payment terms and optional quote expiry before signing. Wallet authentication is
separate and may still prompt for a signature.

The display quote is not a payment or a reservation: show it to the owner before calling
`register()`. Challenge validation does not independently compare that earlier quote or set a
spending budget. Do not reprice the challenged request or automatically sign a replacement after
a submitted request has an uncertain outcome.

## Read the result

After HTTP `202`, `register()` waits using payer-authenticated status reads. On completion, the
result identifies the agent, domain, optional onchain names, NFT token, HTTPS status, metadata
URI, and provisioning state. A legacy HTTP `200` result can still report unfinished provisioning;
it is not proof that all services are ready.

Retain `RegistrationPendingError.handle`. When its registration ID is known, resume with
`waitForRegistration(handle)` or inspect `getRegistration(handle.registrationId)` using the payer's
authentication. Otherwise use `recoverRegistration(handle)` for read-only discovery before
resuming the waiter. No match is not proof that no payment occurred. Timeout or abort stops local
waiting, not an accepted purchase; do not automatically start another checkout. A server-reported
failed or refunded status raises `RegistrationFailedError`, which also does not authorize repayment.

SDK 0.11.1 throws `RegistrationPaymentRejectedError` only for an explicit HTTP `4xx` response
other than `408` satisfying the public rejection schema, including
`paymentSubmission: { status: 'rejected', settlementAttempted: false }`. Its code is
`REGISTRATION_PAYMENT_REJECTED`; it exposes `serverCode`, `message`, `handle`, and
`settlementAttempted: false`. This confirms no settlement attempt for that submission, not payment
success. HTTP `408`, `5xx`, timeouts, network failures, and unconfirmed conflicts remain
`RegistrationPendingError` recovery cases. Neither error authorizes an automatic resend or
replacement payment.

See [asynchronous registration](/sdk/typescript/#asynchronous-registration) for the authentication,
recovery, and completion contract. Service readiness is not guaranteed to be instant.
