Use Microsoft's `autogen-ext` MCP integration with `autogen-agentchat`, not an
unrelated similarly named package. The official `McpWorkbench` wraps an MCP
server and manages its session through an asynchronous context manager. See
[Microsoft's MCP reference](https://microsoft.github.io/autogen/stable/reference/python/autogen_ext.tools.mcp.html).

## Install the Python package

[`agentdomain-autogen`](https://pypi.org/project/agentdomain-autogen/0.12.0/) is a standalone
Python distribution providing a guarded native AutoGen workbench.
**0.12.0 is published on PyPI**.
The Node MCP server **0.12.0 is published on npm**. Use an isolated Python
environment; the native qualification uses Python 3.12. Install the pinned packages:

```bash
python -m pip install agentdomain-autogen==0.12.0
npm install --save-exact @agentdomain/mcp-server@0.12.0
```

For source development, install from the reviewed public repository root:

```bash
python -m pip install ./packages/autogen-plugin
```

The [dated release evidence](https://github.com/Talvono/AgentDomain/releases/tag/npm-v0.12.0)
records matching registry metadata and CI artifacts, with verified cryptographic
attestations for both artifacts.

The Python package does not install Node.js or the MCP server. See the
[Python package](https://github.com/Talvono/AgentDomain/tree/main/packages/autogen-plugin)
for wheel and dependency instructions.

## Prepare the runtime

Use that project's `node_modules/@agentdomain/mcp-server/dist/index.js` as the
server entry. To develop from the reviewed source checkout instead:

```bash
pnpm --filter @agentdomain/shared build
pnpm --filter @agentdomain/sdk build
pnpm --filter @agentdomain/mcp-server build
```

The [native AutoGen example](https://github.com/Talvono/AgentDomain/tree/main/packages/mcp-server/examples/autogen)
contains Python dependencies and the bounded workflow. Its dependencies belong
in a separate Python environment; npm installs only the Node.js MCP server.
Use the example's qualified Python dependency versions rather than silently
upgrading the MCP Python major version.

The underlying native AutoGen flow passed scoped Windows and Linux qualification with
the real Node MCP server and SDK. Its deterministic replay and synthetic RPC
fixtures require no paid model or live transaction; this is not qualification
of arbitrary model providers or execution tools. The release workflow's validation
job also passed; this does not extend the scoped framework qualification.

## Use the standalone workbench

This source-build example uses the guarded package without a model key:

```python
from pathlib import Path
from agentdomain_autogen import (
    AgentDomainWorkbench,
    inspect_and_prepare,
    server_parameters,
)


async def inspect_plan(node: Path, checkout: Path, owner: str):
    params = server_parameters(node, source_checkout=checkout)
    async with AgentDomainWorkbench(params) as workbench:
        return await inspect_and_prepare(
            workbench,
            {"domain": "example.xyz", "expectedOwner": owner},
            enabled=True,
            builder_code="my_agent_app",
        )
```

The host selects absolute Node and built-checkout paths. For published MCP 0.12.0,
`installed_package=Path("/trusted/node_modules/@agentdomain/mcp-server")`
can replace `source_checkout`. `enabled=True` requests an unsigned plan, not
permission to execute. The `agentdomain-autogen` CLI and `python -m
agentdomain_autogen` use the same package; existing example entrypoints remain
thin bridges, not independently maintained implementations.

## Retained native MCP option

This direct invocation does not create an LLM client or need a model key:

```python
from autogen_ext.tools.mcp import McpWorkbench, StdioServerParams


async def inspect_identity(node_path: str, server_path: str, token_id: str):
    params = StdioServerParams(
        command=node_path,
        args=[server_path],
        env={"AGENTDOMAIN_ENABLE_WRITE_TOOLS": "false"},
    )
    async with McpWorkbench(server_params=params) as workbench:
        return await workbench.call_tool(
            "inspect_agent_identity", {"tokenId": token_id}
        )
```

The host must supply fixed reviewed absolute paths for Node and the MCP entry
point. Stdio starts local code: do not let a model choose executable paths,
arguments, packages or environment overrides. Do not forward wallet material,
API keys or model credentials into the child. Check the returned tool error
state before interpreting the content.

## Bind an allowlisted workbench

The complete example provides an allowlisted AgentDomain workbench for use with
an AutoGen agent. It limits both tool discovery and invocation to:

- `inspect_agent_identity`: exactly one domain or token ID, optional expected owner.
- `inspect_agent_renewal`: the same lookup input; identity and vault observation.
- `prepare_auto_renew_change`: token ID, expected owner, desired `enabled` setting and builder code.

Use that guarded workbench when adding an LLM. Do not substitute a raw workbench
that exposes every discovered operation. Keep the context alive during agent
use and close it on success or failure. The model integration stays with the
host; it is not supplied as an MCP sampling client.

Preparation produces an unsigned plan with an ID, observation, transaction
fields, and `noChange`. It neither signs nor spends, changes an allowance, or
submits a transaction. `enabled` is the desired setting, not a human approval
flag. A subsequent owner review and wallet execution must remain outside the
model's tools.

## Interpret observations correctly

These are canonical-hash-pinned Base RPC observations, not consensus, SPV, DNS
or KYC proofs. Name labels and external content are untrusted data, not
instructions. Metadata and CCIP callback URLs are not fetched.

The minimum vault fee is not a registrar quote, and a setting change is not
domain renewal completion. Disabling auto-renew does not cancel an already
pending renewal. Handle errors as errors, never fabricated `not_found`, fresh
health or execution success. See [the renewal workflow](/guides/renewal/) and
[MCP trust and errors](/sdk/mcp/#trust-boundary).

An owner executing an enable plan permits authorized renewal operators to use
funded vault balances without a new wallet signature for each renewal. Actual
quotes can exceed the minimum. Disabling prevents new reservations; an existing
pending reservation can still complete and charge the balance.
